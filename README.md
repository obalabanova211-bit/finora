# Finora

Финансовое приложение для учёта обязательств (РФ и СНГ). Рабочие материалы KIT: `C:\Users\balab\Projects\finance-app-kit`.

## Структура

- `src/domain.ts` — доменная логика: деньги, даты платежей, календарь месяца, финансовая нагрузка, списание «сначала проценты», симуляция закрытия, оценка ставки по графику банка. Без UI, без браузера, без хранения.
- `tests/domain.test.ts` — тесты домена с эталонами.
- `src/store.ts` — состояние модуля «Обязательства»: список, журнал оплат, операции (оплата, отмена, закрытие, секции и итоги). Чистые функции, без React.
- `tests/store.test.ts` — тесты операций.
- `src/persist.ts` — сохранение в браузере (localStorage, ключ finora-v1). Сервера нет, данные остаются на устройстве.
- `src/seed.ts` — демо-данные для кнопки «Показать на примере».
- `app/` — экраны на Next.js: список с секциями (`/`), форма (`/add`, `/edit/[id]`), карточка с окном оплаты (`/item/[id]`). Стили в `app/globals.css` перенесены из одобренного прототипа.

## Правила домена

1. **Деньги — только целые копейки.** `24200000` = 242 000,00 ₽. Никаких float в расчётах: рубли из интерфейса парсятся в копейки из строки (`parseRubToKop`).
2. **Ставки — целые сотые доли процента в год.** `3990` = 39,90%. Проценты за месяц: `round(баланс × ставка / 120000)`.
3. **Списание платежа: сначала проценты, потом тело.** Проценты месяца = остаток × ставка/12; тело = платёж − проценты. Вся история кредита зашита в текущем остатке.
4. **Правило конца месяца:** если в месяце нет такой даты, платёж переносится на последний день месяца (31-е → 28/29-е).
5. **Оценка ставки по графику:** если ставка неизвестна, но известны остаток, платёж и дата окончания — ставка вычисляется обратным расчётом; месяцы целые, поэтому берётся середина диапазона (последний платёж частичный).
6. Слово «долг» не используется (словарь замен — в DECISIONS.md KIT).
7. Одна валюта в пилоте — рубль. Суммы по другим валютам не смешиваются.
